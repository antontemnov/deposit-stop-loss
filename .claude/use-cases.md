## 1. User Management

### UC-1.1: Регистрация через Telegram `/start`
- **Актор**: User
- **Триггер**: Команда `/start` в Telegram боте
- **Основной сценарий**:
  1. User отправляет `/start`
  2. Система проверяет — есть ли user с таким TelegramId
  3. Если нет — создаёт нового User (TelegramId, Username, FirstName, LanguageCode)
  4. Устанавливает default timezone = "Asia/Tbilisi"
  5. Отправляет приветственное сообщение + главное меню
- **Альтернативный**: Если user существует — возвращает "С возвращением!" + главное меню
- **Результат**: User зарегистрирован, может создавать депозиты

### UC-1.2: Изменение настроек пользователя
- **Актор**: User
- **Триггер**: Команда `/settings` или кнопка "Настройки"
- **Сценарии**:
  - Изменить timezone (выбор из предустановленных или ввод вручную)
  - Включить/выключить Telegram-уведомления
  - Включить/выключить Email-уведомления
  - Указать/изменить email
  - Изменить язык (en, ru, ka)
- **Результат**: Настройки обновлены

### UC-1.3: Деактивация аккаунта
- **Актор**: User
- **Триггер**: Команда или кнопка "Удалить аккаунт"
- **Сценарий**:
  1. Подтверждение ("Вы уверены?")
  2. Деактивация User (IsActive = false)
  3. Остановка мониторинга всех депозитов
  4. Уведомления больше не отправляются
- **Альтернативный**: User может реактивировать через `/start`
- **Результат**: Аккаунт деактивирован, данные сохранены

## 2. Deposit Management

### UC-2.1: Создание депозита вручную
- **Актор**: User
- **Триггер**: Команда `/add_deposit` или кнопка "Добавить депозит"
- **Основной сценарий (пошаговый мастер)**:
  1. Выбор банка (TBC / BOG / другой)
  2. Ввод суммы в GEL
  3. Ввод процентной ставки (годовая)
  4. Ввод даты открытия (может быть в прошлом — backdated deposit)
  5. Ввод срока в месяцах
  6. Выбор типа курса (Commercial / Concept)
  7. Ввод порога stop-loss (например, -2%)
  8. Подтверждение всех данных
  9. Система получает текущий курс USD/GEL
  10. Создаёт Deposit aggregate + initial DepositContribution
  11. Если дата в прошлом — запускает backfill исторических курсов
- **Валидация**:
  - Сумма > 0
  - Ставка 0-100%
  - Срок 1-120 месяцев
  - Stop-loss от -50% до 0%
- **Результат**: Депозит создан, мониторинг начат

### UC-2.2: Импорт депозитов из TBC Bank (OAuth)
- **Актор**: User
- **Триггер**: Команда `/connect_bank` → выбор TBC Bank
- **Основной сценарий**:
  1. Генерация OAuth URL с state token
  2. User переходит по ссылке → авторизуется в TBC ID
  3. TBC ID возвращает authorization_code на callback
  4. Backend обменивает code на access_token + refresh_token
  5. Сохраняет токены (зашифрованные) в UserBankConnection
  6. Запрашивает `GET /v2/savings` — список депозитов
  7. Показывает найденные депозиты User-у
  8. User выбирает какие импортировать
  9. Для каждого — создаёт Deposit с Source = TbcApi
- **Ограничения**: Импортированные депозиты readonly (кроме StopLoss)
- **Результат**: Депозиты импортированы, мониторинг начат

### UC-2.3: Просмотр списка депозитов
- **Актор**: User
- **Триггер**: Команда `/my_deposits` или кнопка "Мои депозиты"
- **Сценарий**:
  1. Получить все депозиты User-а
  2. Для каждого: получить последний snapshot / рассчитать текущую доходность
  3. Показать табличный вид с цветовой кодировкой:
     - Зелёный: прибыль > 0
     - Жёлтый: прибыль падает, приближается к stop-loss
     - Красный: stop-loss достигнут
- **Результат**: Список депозитов с текущей доходностью

### UC-2.4: Просмотр деталей депозита
- **Актор**: User
- **Триггер**: Выбор конкретного депозита из списка
- **Сценарий**:
  1. Показать полную информацию: сумма, ставка, дата, банк, статус
  2. Показать текущий курс и доходность в USD
  3. Показать список contributions (все внесения)
  4. Кнопки действий: Пополнить / Редактировать / Пауза / Закрыть / График
- **Результат**: Детальная информация о депозите

### UC-2.5: Просмотр графика доходности (Telegram Mini App)
- **Актор**: User
- **Триггер**: Кнопка "График" в деталях депозита
- **Сценарий**:
  1. Открывается Telegram Mini App (Angular)
  2. Загружает исторические snapshots для депозита
  3. Отрисовывает график:
     - Линия доходности в USD (%)
     - Линия stop-loss threshold (горизонтальная красная)
     - Линия курса USD/GEL (вторая ось)
  4. Интерактивность: zoom, hover details
- **Результат**: Визуализация истории доходности

### UC-2.6: Редактирование депозита
- **Актор**: User
- **Триггер**: Кнопка "Редактировать" в деталях депозита
- **Предусловие**: Deposit.Source == Manual
- **Редактируемые поля**:
  - Дата открытия
  - Процентная ставка
  - Срок в месяцах
  - Сумма (ручная корректировка)
- **Особенности**:
  - При изменении даты — пересчёт MaturityDate
  - При изменении ставки — пересчёт всех исторических snapshots
  - При изменении суммы — пересчёт всех contributions
- **Ограничение**: API-импортированные депозиты — только StopLoss можно менять
- **Результат**: Депозит обновлён, история пересчитана

### UC-2.7: Изменение порога stop-loss
- **Актор**: User
- **Триггер**: Кнопка "Изменить Stop-Loss"
- **Предусловие**: Нет (доступно для ЛЮБЫХ депозитов, включая API-imported)
- **Сценарий**:
  1. Показать текущий порог
  2. User вводит новый порог (от -50% до 0%)
  3. Обновление Deposit.StopLossThreshold
- **Результат**: Порог обновлён, уведомления будут срабатывать по новому порогу

### UC-2.8: Пополнение депозита (Add Funds)
- **Актор**: User
- **Триггер**: Кнопка "Пополнить" или команда `/add_funds`
- **Сценарий**:
  1. User выбирает депозит (если несколько)
  2. Вводит сумму пополнения (в GEL)
  3. Опционально: вводит дату пополнения (может быть в прошлом)
  4. Система получает курс на дату пополнения
  5. Создаёт новый DepositContribution
  6. Обновляет CurrentAmount
  7. Показывает обновлённую информацию
- **Предусловие**: Deposit.Status == Active
- **Результат**: Contribution добавлен, средневзвешенный курс пересчитан

### UC-2.9: Редактирование конкретного внесения (Contribution)
- **Актор**: User
- **Триггер**: Выбор конкретного contribution из списка → "Редактировать"
- **Редактируемые поля**:
  - Сумма
  - Дата внесения
  - Курс на момент внесения (ручная коррекция)
- **Особенности**:
  - Пересчёт CurrentAmount
  - Пересчёт средневзвешенного курса
  - Пересчёт USD value этого contribution
- **Результат**: Contribution обновлён, депозит пересчитан

### UC-2.10: Удаление конкретного внесения (Contribution)
- **Актор**: User
- **Триггер**: Выбор конкретного contribution → "Удалить"
- **Предусловие**: Нельзя удалить единственное (initial) внесение
- **Сценарий**:
  1. Подтверждение удаления
  2. Удаление DepositContribution
  3. Пересчёт CurrentAmount
  4. Пересчёт средневзвешенного курса
- **Результат**: Contribution удалён

### UC-2.11: Приостановка мониторинга (Pause)
- **Актор**: User
- **Триггер**: Кнопка "Пауза"
- **Сценарий**:
  1. Deposit.Status → Paused
  2. Background jobs перестают мониторить этот депозит
  3. Уведомления не отправляются
- **Предусловие**: Deposit.Status == Active
- **Результат**: Мониторинг приостановлен

### UC-2.12: Возобновление мониторинга (Resume)
- **Актор**: User
- **Триггер**: Кнопка "Возобновить"
- **Предусловие**: Deposit.Status == Paused
- **Результат**: Мониторинг возобновлён

### UC-2.13: Закрытие депозита
- **Актор**: User
- **Триггер**: Кнопка "Закрыть депозит"
- **Сценарий**:
  1. Подтверждение ("Вы уверены?")

  3. Deposit.Status → Closed, ClosedAt = now
  4. Мониторинг прекращён
  5. Показать итоговую статистику (profit/loss)
- **Результат**: Депозит закрыт, доступен в истории

### UC-2.14: Просмотр закрытых депозитов (история)

- **Триггер**: Фильтр "Закрытые" в списке депозитов
- **Результат**: Список закрытых депозитов с финальной доходностью

## 3. Exchange Rates

### UC-3.1: Просмотр текущего курса
- **Актор**: User
- **Триггер**: Команда `/current_rate` или кнопка "Текущий курс"
- **Сценарий**:
  1. Получить последний курс из БД
  2. Если курс старше 1 часа — предупредить
  3. Показать:
     - NBG official rate
     - TBC Commercial buy/sell
     - TBC Concept buy/sell (если применимо)
- **Результат**: Текущие курсы отображены

### UC-3.2: Просмотр истории курсов
- **Актор**: User
- **Триггер**: Кнопка "История курсов" / Graph в Mini App
- **Сценарий**:
  1. Выбор периода (неделя, месяц, 3 месяца, год, всё время)
  2. Выбор источника (TBC Commercial, TBC Concept, NBG)
  3. Показать график курса USD/GEL
- **Результат**: График истории курсов

### UC-3.3: Автоматический сбор курсов (Background Job)
- **Актор**: System
- **Триггер**: Cron расписание (каждые 10 минут для TBC/BOG, 1 раз/день для NBG)
- **Основной сценарий**:
  1. ExchangeRateFetchJob запускается по расписанию
  2. Для каждого активного банка:
     a. Запросить курсы через IExchangeRateProvider
     b. Если курс изменился с последнего сохранённого → сохранить в БД
     c. Если API недоступен → fallback на NBG
     d. Если все API недоступны → использовать последний кэшированный
  3. Логировать результат
- **Fallback chain**: TBC API → NBG API → Cached rate
- **Результат**: Курсы обновлены в БД

### UC-3.4: Backfill исторических курсов
- **Актор**: System
- **Триггер**: Создание депозита с датой в прошлом (UC-2.1)
- **Сценарий**:
  1. Определить диапазон дат (openedAt → today)
  2. Проверить какие даты уже есть в БД
  3. Для отсутствующих дат:
     a. Запросить NBG API (поддерживает исторические данные)
     b. Rate limiting: максимум ~20 запросов за backfill
  4. Сохранить исторические курсы в БД
- **Результат**: Исторические курсы заполнены

## 4. Monitoring & Notifications

### UC-4.1: Мониторинг депозитов (Background Job)
- **Актор**: System
- **Триггер**: DepositMonitorJob (каждые 5 минут)
- **Основной сценарий**:
  1. Получить все Active депозиты
  2. Для каждого:
     a. Получить последний курс из БД
     b. Рассчитать: accrued interest, total amount, profit/loss %
     c. Создать DepositSnapshot
     d. Проверить notification triggers:
        - CRITICAL: profit ≤ 0% → уведомить (cooldown 1h)
        - WARNING: до stop-loss осталось 2-4% → уведомить (cooldown 12h)
        - INFO: profit < expected rate → уведомить (cooldown 24h)
     e. Если trigger сработал → создать Notification (status=Pending)
- **Результат**: Snapshots созданы, notifications в очереди

### UC-4.2: Отправка уведомлений (Background Job)
- **Актор**: System
- **Триггер**: NotificationSenderJob (каждые 2 минуты)
- **Сценарий**:
  1. Получить все Pending notifications
  2. Для каждого:
     a. Определить User.TelegramId
     b. Отправить через Telegram Bot API
     c. Если успешно → MarkAsSent()
     d. Если ошибка → MarkAsFailed(errorMessage)
  3. Failed notifications будут retry на следующем цикле
- **Результат**: Уведомления отправлены пользователям

### UC-4.3: Просмотр истории уведомлений
- **Актор**: User
- **Триггер**: Кнопка "Уведомления" или `/notifications`
- **Сценарий**:
  1. Показать список уведомлений (последние 50)
  2. Группировка по депозиту
  3. Цветовая кодировка по уровню (Info/Warning/Critical)
  4. Кнопка "Отметить прочитанными"
- **Результат**: Список уведомлений отображён

### UC-4.4: Cooldown уведомлений
- **Актор**: System
- **Логика**: Не отправлять уведомление того же уровня для того же депозита чаще чем:
  - INFO: 1 раз в 24 часа
  - WARNING: 1 раз в 12 часов
  - CRITICAL: 1 раз в 1 час
- **Проверка**: Перед созданием Notification — запросить GetLastByDepositAndLevelAsync

## 5. Bank OAuth Integration

### UC-5.1: Подключение банка (TBC)
- **Актор**: User
- **Триггер**: Команда `/connect_bank`
- **Сценарий**: См. UC-2.2 (OAuth flow)
- **Результат**: UserBankConnection создана

### UC-5.2: Синхронизация депозитов из банка
- **Актор**: User / System (by schedule)
- **Триггер**: Ручной запрос или автоматическая синхронизация
- **Сценарий**:
  1. Проверить UserBankConnection.IsActive
  2. Если token expired → refresh через refresh_token
  3. Запросить `GET /v2/savings`
  4. Сравнить с существующими депозитами
  5. Обновить изменённые данные (сумма, статус)
  6. Если банк закрыл депозит → обновить Status
- **Результат**: Данные депозитов синхронизированы

### UC-5.3: Отключение банка
- **Актор**: User
- **Триггер**: Кнопка "Отключить банк"
- **Сценарий**:
  1. Подтверждение
  2. UserBankConnection.Disconnect()
  3. Revoke tokens в банке (если поддерживается)
  4. Депозиты остаются, но больше не синхронизируются
- **Результат**: Банк отключён

### UC-5.4: Refresh OAuth токена
- **Актор**: System
- **Триггер**: Перед любым API-вызовом к банку
- **Сценарий**:
  1. Проверить UserBankConnection.IsTokenExpired()
  2. Если expired → POST refresh_token к TBC API
  3. Обновить access_token + refresh_token + expires_at
  4. Если refresh провалился → деактивировать connection, уведомить User
- **Результат**: Токен обновлён

## 6. Admin Operations

### UC-6.1: Уведомление админа об ошибках
- **Актор**: System
- **Триггер**: Unhandled exception в API / Background Jobs
- **Сценарий**:
  1. ExceptionHandlingMiddleware ловит исключение
  2. Логирует через Serilog
  3. Отправляет уведомление админу через отдельный Telegram Bot
  4. Опционально: дублирует на email
- **Содержание уведомления**: Error message, stack trace, endpoint/job, timestamp, traceId
- **Результат**: Админ уведомлён

### UC-6.2: Уведомление админа о проблемах с API
- **Актор**: System
- **Триггер**: Exchange rate provider вернул ошибку
- **Сценарий**:
  1. При fallback с основного провайдера → WARNING
  2. Если все провайдеры недоступны → CRITICAL
  3. Отправка через AdminNotificationService
- **Результат**: Админ знает о проблемах с внешними API

### UC-6.3: Очистка старых данных (Background Job)
- **Актор**: System
- **Триггер**: CleanupJob (ежедневно в 2:00 AM)
- **Сценарий**:
  1. Удалить notifications старше 30 дней
  2. Для каждого депозита: оставить последние N snapshots, удалить остальные
  3. Exchange rates: оставить последние 2 года
  4. Логировать количество удалённых записей
- **Результат**: БД очищена от устаревших данных

## 7. Calculations (Core Business Logic)

### UC-7.1: Расчёт накопленных процентов
- **Актор**: System (используется в UC-4.1)
- **Формула**: `principal * (rate / 100) * (days / 365)`
- **Особенности**:
  - Учитывает contributions с разными датами
  - Каждый contribution начисляет проценты от своей даты
- **Результат**: Общая сумма накопленных процентов в GEL

### UC-7.2: Расчёт текущей стоимости в USD
- **Формула**: `(total_gel + accrued_interest) / current_sell_rate`
- **Используемый курс**: Sell rate банка (для конвертации GEL → USD)
- **Результат**: Текущая стоимость депозита в USD

### UC-7.3: Расчёт прибыли/убытка в %
- **Формула**: `((current_usd - initial_usd) / initial_usd) * 100`
- **Для множественных contributions**: Используется средневзвешенный initial USD value
- **Результат**: Процент прибыли/убытка в USD

### UC-7.4: Средневзвешенный курс (Weighted Average Rate)
- **Формула**: `Σ(amount_i * rate_i * days_i) / Σ(amount_i * days_i)`
- **Используется**: Когда у депозита > 1 contribution
- **Результат**: Средневзвешенный курс для корректного расчёта P&L

### UC-7.5: Пересчёт истории при изменении параметров
- **Триггер**: UC-2.6 (редактирование депозита), UC-2.9 (редактирование contribution)
- **Сценарий**:
  1. Получить все snapshots для депозита
  2. Удалить все snapshots
  3. Для каждого исторического курса: пересчитать snapshot с новыми параметрами
  4. Сохранить новые snapshots
- **Результат**: История доходности пересчитана

## Нереализованные / Спорные сценарии

### ❓ UC-X.1: Множественные валюты для одного депозита
- Депозит в EUR, конвертация EUR → USD?
- Нужно ли поддерживать EUR/GEL пару сейчас?
- **Текущее решение**: MVP только GEL → USD. EUR в v2.0.

### ❓ UC-X.2: Частичное снятие с депозита (Withdrawal)
- Если банк позволяет частичное снятие — нужно ли отражать?
- Это обратная операция к AddFunds
- **Текущее решение**: Не в MVP. Можно добавить "negative contribution" позже.

### ❓ UC-X.3: Автоматическое закрытие по MaturityDate
- Должна ли система автоматически закрывать депозит по истечении срока?
- Или просто уведомить User?
- **Рекомендация**: Уведомить, но НЕ закрывать автоматически (банк может пролонгировать).

### ❓ UC-X.4: Депозит в USD (обратная ситуация)
- User держит долларовый депозит — нужно ли?
- Логика инвертируется: profit когда GEL слабеет, loss когда GEL укрепляется
- **Текущее решение**: Не в MVP. Архитектура Currency-agnostic, можно добавить.

### ❓ UC-X.5: Сравнение банков
- "TBC предлагает 12%, BOG — 13.5% при одинаковом курсе"
- Фича-советник
- **Текущее решение**: v2.0+ (AI Recommendations)

### ❓ UC-X.6: Экспорт данных
- CSV/Excel/PDF отчёт по депозитам и истории
- **Текущее решение**: v1.1

### ❓ UC-X.7: Multi-device sync
- User заходит с двух устройств Telegram (phone + desktop)
- Проблем нет: данные на сервере, бот stateless (FSM state в Redis)

### ❓ UC-X.8: Аутентификация Web Dashboard
- Стратегия: Telegram Login Widget? Magic link через бота? Обычный email/password?
